## 3. 详细评测结果分析

### 3.1 功能回归测试 (LLM-as-a-Judge)
*   **通过情况**: 在已完成的 Case 中，核心功能如 `search-budget` (预算硬约束)、`memory-write` (偏好写入) 均获得 **PASS**。
*   **主要问题**:
    *   **超时风险**: 涉及多轮对话和长期记忆回溯的 Case（如 `memory-recall`）处理耗时较长，易触发 HTTP 超时。
    *   **细节一致性**: 在 `incomplete-product-info-honesty` 中发现库存数字与数据库存在微小偏差（149 vs 150），需同步数据源。
*   **评分分布**: P0（事实与安全）通过率较高，P2（表达质量）表现稳定。

### 3.2 商品召回测试 (Vector Search)
*   **策略**: `embedding_rerank` (向量检索 + 余弦相似度排序)
*   **指标表现**:
    *   **Recall@8**: 0.611 (阈值 ≥ 0.75) 
    *   **MRR**: 0.500 (阈值 ≥ 0.65) 
    *   **NDCG@8**: 0.502 (阈值 ≥ 0.7) ❌
*   **原因分析**:
    *   **语义类 Query 表现极佳**: 对于“坐飞机脖子难受”这类不含商品名的查询，召回率接近 100%。
    *   **字面/精确匹配短板**: 新增的大量 ID 直查（如 `P1001`）和品牌查询（如 `Anker`）在纯向量空间中的匹配效果不如关键词检索。
    *   **空结果影响**: 库中不存在的品牌（小米、无印良品）导致部分 Case 召回率为 0，拉低了整体均值。

### 3.3 品类知识测试 (RAG)
*   **指标表现**:
    *   **Recall@5**: 0.881 ✅
    *   **MRR**: 0.691 ✅
    *   **NDCG@5**: 0.739 ✅
*   **结论**: 知识库切片与 Embedding 质量较高，能够准确将用户关于“怎么选”、“有什么区别”的问题映射到对应的 Markdown 文档。

## 4. 优化建议

### 4.1 短期优化 (Quick Wins)
1.  **启用混合检索**: 在生产环境中，不要仅依赖向量检索。建议采用 **Keyword (BM25) + Vector** 的加权混合策略，以解决 ID 直查和品牌匹配的短板。
2.  **数据源同步**: 检查 `app.infrastructure.persistence` 层，确保 Agent 读取的库存数字与 `ground_truth` 完全一致，避免 P0 级事实错误。
3.  **增加超时配置**: 在 `eval_regression.py` 中增加 `timeout` 参数，或为长链路 Case 设置更长的等待时间。

### 4.2 长期规划
1.  **引入 Reranker 模型**: 当前 `embedding_rerank` 因未配置 Reranker 而退化为 `embedding_only`。接入专用的 Rerank 模型（如 Qwen-Rerank）可显著提升 Top-K 的排序质量。
2.  **Qdrant 服务化**: 建议将 Qdrant 从本地嵌入模式迁移至 Docker 容器服务，以支持后端服务与评测脚本的并发访问，解决文件锁冲突问题。
3.  **自动化 CI/CD**: 将 `validate_datasets.py` 和 `run_product_recall.py --strategy keyword_2gram` 接入 GitHub Actions，确保每次代码提交都能快速通过基础体检。
